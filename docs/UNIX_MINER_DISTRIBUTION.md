# Linux and macOS miner distribution boundary

Linux/macOS end-user miner materialization is currently **quarantined**. The repository retains the archive tooling and launcher contract for future use, but CI must not create, attest, upload, or publish `ZyronMiner-linux-<arch>.tar.gz` or `ZyronMiner-macos-<arch>.tar.gz` candidates until the handle-relative filesystem custody prerequisite tracked in #761 is implemented and the dependent release-root/bundle-root/nested-destination stop-ships (#757, #683, #636) are resolved with regression evidence.

While quarantine is active, the Unix archive candidate workflow runs on the matching Linux/macOS runners, typechecks and audits the runtime, verifies the inactive canonical network profile, and proves that invoking self-contained miner packaging fails before `miner-release` is created or any candidate byte is materialized. The quarantine has no environment or CLI bypass. Archive packaging, SBOM generation inside the release root, attestation, artifact upload, and promotion are intentionally disabled rather than being treated as readiness evidence.

Public mining activation remains a separate gate. When packaging is eventually restored, candidates must still retain `publicMiningActivated=false`, `releaseEligible=false`, `platformSigningVerified=false`, and `publicationAllowed=false` until immutable release provenance, required platform signing/notarization, explicit activation approval, and the other public-launch requirements are satisfied. The website download control must remain fail-closed until those requirements are met.
