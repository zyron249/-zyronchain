# Miner runtime source snapshot boundary

Miner release-candidate runtime materialization is fail-closed against in-place regular-file mutation, pathname replacement, and symlink traversal at the descriptor-open boundary.

For each ordinary regular source file and each canonical in-root npm symlink target, the materializer binds the validated source to a descriptor snapshot containing device/inode identity, byte size, modification time, and change time. On supported POSIX packaging targets the source descriptor is opened with `O_RDONLY|O_NOFOLLOW`; candidate destination files are opened with `O_WRONLY|O_CREAT|O_EXCL|O_NOFOLLOW`. A source pathname replaced by a symlink immediately before `open` therefore fails closed instead of traversing the replacement target. Explicit npm symlinks that were already validated as in-root regular-file targets remain supported by resolving the allowed link first and applying the no-follow open to that canonical target path.

The opened source descriptor must still match the pre-open snapshot before any destination file is created. After all source bytes have been read, the descriptor is revalidated again; an in-place mutation during the copy aborts candidate construction rather than accepting a mixed or post-validation byte stream. Platforms that cannot provide a non-zero `O_NOFOLLOW` capability do not receive a pathname-following fallback from this helper.

This rule complements, and does not replace, source-root confinement, directory identity checks, destination freshness/atomic creation, strict release-manifest coverage, platform signing/notarization, provenance, immutable-release review, or explicit public-mining activation. Passing this boundary is local release-candidate integrity evidence only and is not public-mining, public-testnet, or mainnet readiness evidence.
