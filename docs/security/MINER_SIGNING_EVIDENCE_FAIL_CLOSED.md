# Miner platform-signing evidence boundary

`platformSigningVerified=true` is a release stop-ship assertion, not a value inferred from candidate CI. The miner promotion gate must therefore reject a promotion unless each canonical Windows, macOS, and Linux signing/notarization evidence reference is byte-bound to a regular non-symlink file in the exact checked-out source tree.

For an active promotion, the terminal `#sha256=` value on each signing evidence URL must equal the SHA-256 of the referenced evidence file bytes. The file must use signing evidence schema version 3 and contain exactly the promoted `releaseVersion`, exact 40-hex `sourceCommit`, the same-platform artifact name/digest, the exact corresponding SBOM name/digest, and a `verification` object. `verification.verified` must be literal `true`; the verification method must be platform-approved (`authenticode` for Windows, `codesign` or `notarization` for macOS, `detached-signature` for Linux), and the tool identity must be explicit and bounded. Metadata-only subject commitments, false/unknown verification, digest drift, cross-platform substitution, mutable branch references, missing evidence files, symlinks, and non-regular evidence fail closed.

This repository check validates evidence structure, subject identity, local byte binding, and the declared successful verification result. It does **not** create a signature, notarize an application, provision signing credentials, independently establish signer trust, publish a GitHub Release, or authorize public mining. Real platform/tool-produced signing or notarization evidence remains required and reviewable under issue #390 before any release publication or website download activation.

The inactive canonical promotion policy remains unchanged: all activation/publication verification flags are false, release identity and platform assets are null, and no signing evidence is accepted as authority merely because packaging or release-candidate CI succeeded.
