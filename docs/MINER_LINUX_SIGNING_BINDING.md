# Linux miner signing promotion boundary

Miner release promotion schema v4 requires Linux signing evidence in addition to Windows signing and macOS signing/notarization evidence. The inactive canonical policy keeps `linuxSigning` null; a promotion attempt cannot satisfy `platformSigningVerified=true` without reviewable Linux signing evidence.

The only accepted Linux signing role paths are `evidence/linux-signing.json` and `evidence/linux-signature.json` at the exact promoted `sourceCommit`, with a lowercase 64-hex `#sha256=` binding. Mutable branch references, unrelated evidence paths, digestless references, symlinks and non-regular evidence files fail closed.

For an active promotion, that digest binds the actual checked-out evidence-file bytes rather than a metadata-only approval token. The evidence must use signing schema version 3 and exactly identify the promoted `releaseVersion`, `sourceCommit`, Linux artifact `{platform,name,sha256}`, and its canonical same-release SBOM `{name,sha256}`. Its verification result must be explicitly `verified=true`, use the reviewed Linux `detached-signature` method, and identify the verification tool. Missing evidence, false/unknown verification, cross-platform substitution, filename or digest drift, mutable/non-canonical SBOM evidence, evidence-byte digest mismatch and artifact/SBOM digest aliasing therefore fail closed.

This is an evidence-contract and byte-binding gate only. It does not select or provision a private signing key, independently establish signer trust, perform the signature verification itself, grant GitHub OIDC or write authority, publish a release asset, make an existing release immutable, activate public mining, or establish public-testnet/mainnet readiness. Real tool-produced signature verification, signer custody and independently reviewable release evidence remain stop-ship requirements.
