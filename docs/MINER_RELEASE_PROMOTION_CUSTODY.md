# Miner release promotion action custody

The miner release promotion gate protects a high-value publication boundary, so its GitHub Actions dependencies are pinned to reviewed immutable commit SHAs and checkout credentials are not persisted.

This policy preserves the exact Node.js 22.23.2 runtime plus the canonical fail-closed promotion verifier and its positive/negative vectors. It also requires the provenance, platform-signing, checksum, immutable-release, and public-mining-activation subject-binding verifiers and their regressions to remain present in the read-only promotion workflow. Provenance is not accepted as a metadata-only digest commitment: active promotion requires a structured schema-v3 provenance document stored as an exact regular-file Git blob at the promoted source commit, byte-bound by the terminal SHA-256, matched by the checked-out non-symlink copy, bound to the exact promoted artifact/SBOM subjects, and carrying an explicitly positive approved verification method/tool identity. The checksum binding specifically prevents a canonical checksum evidence reference from satisfying promotion unless its terminal digest commits to the exact ordered Windows, macOS, and Linux promoted artifact filenames and SHA-256 identities. The public-mining activation binding likewise prevents a canonical activation evidence path from being reused for a different miner release, source commit, or promoted platform artifact set.

A passing custody policy proves only that the CI execution boundary and required local policy checks have not drifted; it does not prove that real provenance was externally produced or independently reviewed, platform signing/notarization occurred, checksums were externally published, a GitHub Release is immutable, public mining was activated, or public-testnet/mainnet readiness exists.

`docs/miner-release-promotion.json` remains the canonical fail-closed release policy. Publication and public mining must remain disabled until their separately reviewed evidence is complete.
