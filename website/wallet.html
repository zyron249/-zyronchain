What works today

  • WORKS NOWCreate an encrypted wallet

    Offline, on your own computer, with the canonical CLI at a pinned release. The password is asked for in the terminal and checked for strength.

  • WORKS NOWNo password file left behind

    The scripts keep the password in memory and a private temporary file only for the seconds the CLI needs it, then shred it.

  • WORKS NOWTest your backup

    The verify script decrypts your backup locally and confirms it re-derives the same address and hash.

  • WORKS NOWChecksummed addresses

    The checker below and the create script show a mixed-case display checksum that catches typos. The plain lower-case form stays valid and is what the chain uses. CLI support is in PR #921.

  • IN REVIEWStronger keystore (v2)

    scrypt N=2^17 with v1→v2 migration is implemented in draft PR #921. Until it is merged, new keystores use v1 (N=2^15), which will stay readable.

  • NOT LIVEBalance and transfers

    There is no public wallet RPC yet, so no balance can be shown and no transfer can be sent.

  • RETIREDMining

    Mining is retired. There are no mining rewards to claim with a wallet.

  • IN PROGRESSHardened page headers

    This page refuses to run inside a frame and sends no referrer. Server-side HSTS and framing headers are pending a hosting setting.

  • DESIGN50,000,000 ZYN fixed supply

    The fixed-supply design is not yet activated on a public network.

01Generate

The canonical CLI creates a fresh secp256k1 private key using the operating system cryptographic random source.

New keystores use scrypt-derived encryption keys and AES-256-GCM authenticated encryption.

The website never receives the password, private key, keystore file or signing request.

01 / CREATE

Generate the wallet
on your machine.

Choose a task and your operating system. The script checks out the exact canonical release revision shown below, installs the locked L1 dependencies, builds the CLI and asks for the wallet password (twice) inside your local terminal, rejecting weak passwords. No password file is kept: it exists only in a private temporary file for the few seconds the CLI needs it and is then shredded. Right after creating the wallet it runs a restore test and prints the address, its checksummed form and the keystore SHA-256 for your backup records. For automation only, ZYRON_WALLET_PASSWORD skips the prompt (the script warns: environment variables can leak to other processes of your user, shell history and CI logs).

02 / BACKUP

Keystore + password.
Two separate backups.

The encrypted keystore and its password are both required for local signing. The scripts do not save the password anywhere, so remember it or write it down offline. Keeping it next to the keystore defeats part of the protection provided by encryption.

  1. Write down the address and the Keystore SHA-256 the script prints.
  2. Copy wallet.json to one offline medium and keep the password (on paper or in an offline password manager) in a different place.
  3. Test the copy with 2 · Verify / restore a backup above. It asks for the password and must print the same address and hash.
  4. Restore on a new computer the same way: run the verify script against your backup, then use the verified keystore with the CLI.

03 / CHECK

Check an address
before you share it.

ZyronChain addresses are ZYN + 40 lower-case hex characters, derived as the first 20 bytes of SHA-256 of the 64-byte secp256k1 public key. The consensus form has no checksum, so ZyronChain also defines a display-only checksum: some letters are upper-cased according to SHA-256 of the address (like Ethereum's EIP-55). A wrong upper/lower-case pattern means a typo. The plain lower-case form stays valid everywhere and is what the chain stores (spec ↗). This checker runs entirely in your browser; it never asks for a private key, password or keystore.

Paste a ZYN address, a public key, or both.

Never paste a private key anywhere, including here. A public key and an address are safe to share.

05 / SAFETY

The wallet rule:
the secret does not travel.

NEVEREnter a wallet password on zyronchain.com

The canonical website intentionally has no password field for wallet creation.

NEVERUpload wallet.json to “verify” a wallet

The website has no wallet-upload workflow and should never request one.

CHECKConfirm the address before receiving funds

Use the address stored in the authenticated keystore and compare it carefully when copying.

CHECKConfirm chain ID and public endpoint

Do not use rehearsal/private endpoints as though they were the activated public network.

NEVERTrust anyone offering a “recovery” or “airdrop claim”

ZyronChain has no support desk that needs your files, and mining rewards do not exist (mining is retired).

Key
secp256k1, 32 bytes from the OS CSPRNG (crypto.randomBytes), redrawn if outside the valid range
Address
ZYN + first 40 hex of SHA-256(64-byte public key x||y)
KDF
Current release (v1): scrypt N=32768, r=8, p=1, fresh 32-byte random salt per keystore. v2 in review (PR #921): N=131072 (2^17), parameters bound into the authenticated data, v1 still readable and migratable
Cipher
AES-256-GCM, fresh 12-byte random IV, 16-byte authentication tag; public key + address bound as associated data
Decrypt check
Wrong password or any tampering fails authentication; the decrypted key must re-derive the stored public key and address
Password
Scripts require 12+ characters, 6+ distinct characters and about 60+ estimated bits; a long random passphrase is strongly recommended. Never stored by the scripts
Checksum
Display only: letter i upper-cased when nibble i of SHA-256("zyronchain/address-checksum/v1:" + address) ≥ 8. Consensus unchanged
