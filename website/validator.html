Operator checklist

      
Before you run a validator.

      
An operator-assistance tool, not a one-click validator. Every step runs on your machine; nothing is uploaded.

      

        
01Hardware and OS
A 64-bit Linux or macOS host (Windows via WSL2) with Node.js 22 or 24, a persistent disk and a stable connection. No official minimum is published yet: target-hardware measurements are an open activation requirement.

        
02Canonical repository
Clone only github.com/zyron249/-zyronchain and check out the exact release commit shown above. The scripts verify the commit with git cat-file -e before building.

        
03Identity setup
The identity script creates an encrypted validator keystore locally (chmod 600). Share only the address, public key and PeerId. Never send the keystore or its password.

        
04Genesis verification
Every validator must use byte-identical genesis. Compare its SHA-256 with the coordinator over a second channel. The start script refuses genesis with placeholder values.

        
05Peers and bootstrap
List explicit peers as multiaddrs with the expected /p2p/<PeerId> suffix, so a wrong host cannot impersonate a validator.

        
06Firewall
Open only the P2P TCP port to the other validators. Keep everything else closed.

        
07Public vs private RPC
Consensus RPC binds to 127.0.0.1 and must never be exposed to the Internet. A public interface, if ever offered, must be a separate bounded read-only gateway.

        
08Activation status
Public testnet: authorized by governance, not activated. Only friends/private, non-value testnets can be run today.

        
09Recovery
Back up the encrypted keystore and its password separately and offline. Rehearse a restore before relying on it. Losing both means losing the identity.

Operator safety

      
What the website deliberately cannot do.

      

        
01No browser validator process
Browsers cannot safely provide stable inbound raw TCP, durable background consensus or production key custody. The website launches a local operator workflow instead.

        
02No private-key upload
The launchpad neither requests nor stores validator private keys, passwords or HSM credentials.

        
03No direct validator RPC
Consensus RPC remains loopback-only by default. Public interfaces must use a separately bounded read-only gateway.

        
04No fake public launch
Friends/private testnets are available now; public-network enrollment stays disabled until activation evidence is actually closed.
