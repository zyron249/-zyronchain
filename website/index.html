Protocol architecture

Separate the responsibilities.
Make the boundaries explicit.

Mining competes for issuance. Validators finalize the canonical chain. Wallet keys remain with the user. Authenticated state lets independent software verify what the network claims.

Permissionless issuance

Proof of Work issues ZYN.
Validators still finalize.

Protocol-v5 miners search locally for tip-bound SHA-256 work, sign successful claims with their own key and submit them to the network. Mining does not choose the canonical chain; validator quorum finality remains a separate security boundary.

Security model

Security is a set of boundaries,
not a marketing adjective.

The implementation treats signing, persistence, RPC admission, checkpoint restoration, protocol upgrades and release provenance as explicit security surfaces.

01

Fail-closed activation

Capabilities that require launch evidence remain disabled when that evidence is incomplete or ambiguous.

02

Local encrypted custody

Canonical wallet and miner flows use encrypted local keystores. Browser pages remain onboarding surfaces—not secret holders.

03

Bounded public interfaces

RPC and networking paths are designed around strict schemas, response bounds, rate limits and network-identity validation.

04

Recovery with verification

Snapshots and checkpoints are accepted only when authenticated state and chain identity match the expected network.

05

Release provenance

Release candidates, checksums, SBOMs and activation evidence are kept distinct from permission to publish or activate value-bearing use.

06

Verify the implementation

The repository is public so security claims can be checked against the code and test boundaries directly.
