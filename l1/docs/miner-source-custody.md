# Miner package source custody

POSIX miner source custody is a hardening control for the quarantined miner packaging path. It is not a public-mining activation mechanism.

The production POSIX materializer now binds source roots inside the same native custody session that owns the destination release tree. Canonical repository directories are entered with retained `openat()` directory descriptors before their files are copied, and candidate files are opened relative to the currently retained source directory with `O_NOFOLLOW`. The bundled Node runtime is copied only after binding its canonical parent directory, and generated `ZyronMiner`/`README.txt` sources are copied only after binding the private staging directory. Source symlinks fail closed rather than falling back to pathname copy. Destination creation remains descriptor-relative, exclusive, no-follow, fsynced, and rooted under the retained `miner-release` descriptor.

This closes the previous production use of absolute pathname `COPY` for candidate bytes on POSIX, but it does not make mining release-ready. The standalone source-custody regression helper still provides deterministic source-root, nested-directory, and same-path regular-file replacement evidence; the production materializer regression additionally enforces the retained `SOURCE`/`SOURCE_ENTER`/`COPYREL` protocol and source-symlink rejection. A Windows handle/reparse-safe source-and-destination equivalent remains absent, so Windows packaging stays fail closed. Broader miner quarantine and activation gates also remain enabled under #761.

Before public-mining activation, the retained production path still requires complete release-candidate evidence on the real dependency tree and fixed-SHA green general ZyronChain CI, Standalone L1 Node 22/24, Miner Package CI, Miner Release Candidate CI, and every other applicable security/readiness gate. Package availability or POSIX custody hardening must not be represented as public mining, public testnet, or mainnet readiness.
